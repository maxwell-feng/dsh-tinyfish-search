# 发行说明 — v0.13.0

[英文](RELEASE.md) | 中文

发行日期：2026-09-28

**dsh-tinyfish-search** 0.13.0 完成与 DeepSeek Harness 0.2.0-rc.1 的对齐。本版不改运行时逻辑、不改配置、不改工具接口，行为与 0.12.0 完全一致——唯一区别是本插件现在能通过 0.2.0-rc.1 强制执行的 peer 兼容性闸门。

## 变更

- **宿主对齐**：开发依赖升级到 DeepSeek Harness 0.2.0-rc.1，并已针对该版本完成验证。
- **peer 区间放宽为 `>=0.1.7-alpha.2 <0.3.0`**：DeepSeek Harness 0.2.0-rc.1 会在接纳插件行之前，用正在运行的运行时版本校验每一条 `@deepseek-ai/dsh*` peer 区间，且预发行版参与区间匹配。原先的 `^0.1.7-alpha.2` 区间不含 `0.2.x`，因此 `0.12.0` 在 `0.2.0-rc.1` 上会被拒绝；放宽后的区间同时接纳 `0.2.x` 线（含 `0.2.0-rc.1`）与自 `0.1.7-alpha.2` 至 `0.1.7-rc.2` 的整条 `0.1.7` 预发行线。`engines.dsh` 使用同一区间，Node 引擎区间未改动。
- **接缝核对**：本插件使用的全部接口在 0.1.7-rc.2 与 0.2.0-rc.1 源码中完全一致——web 搜索提供方接缝、凭据解析、Host 读取的易变配置 schema，以及启动环境查询。
- **源码改动**：插件源码只有一处变动，即 `USER_AGENT` 版本常量。
- **供应链闸门**：工作区文件现对 0.2.0-rc.1 的包集合豁免 pnpm 的最小发布年龄闸门，否则 DSH 持续发布的预发行版会被拦下。
- **文档**：安装、更新、配置、使用、卸载五份指南的中英双语版本均已更新为 0.13.0 的版本横幅与命令，其中的兼容性闸门章节也写明了 0.2.0-rc.1 会拒绝哪些插件版本。

## 升级

执行 `dsh plugin --profile web add dsh-tinyfish-search@0.13.0`，或让 profile 跟踪最新发行版即可。无需任何手工步骤：配置字段、取值与默认值均未改动。使用 DeepSeek Harness 0.2.0-rc.1 的用户必须升到 0.13.0——`0.12.0` 在该版本上会被拒绝，而 `dsh plugin allow-version` 只是显式接受风险的覆盖手段，并非兼容性修复。完整历史见 CHANGELOG.zh.md。

## 验证

- 类型检查与构建均干净，22 项单元测试在 DeepSeek Harness 0.2.0-rc.1 的各包上全部通过。
- 冻结锁文件安装通过 pnpm 的供应链策略校验。
- 以宿主自己发布的 `evaluatePluginCompatibility`（`@deepseek-ai/dsh-app-boot@0.2.0-rc.1`）实测：运行时版本为 `0.2.0-rc.1`，`dsh-tinyfish-search@0.13.0` 在 `0.2.0-rc.1`、`0.2.0`、`0.1.7-rc.2`、`0.1.7-alpha.2` 上均准入，而 `dsh-tinyfish-search@0.12.0` 因 `^0.1.7-alpha.2` peer 在 `0.2.0-rc.1` 上被拒绝。
- 实际打包的 0.13.0 压缩包含构建产物 `lib/`、`cordis.patch.yml` 与 `LICENSE`，其清单即上述闸门所准入的那一份。
